# Ticket 07 private-evidence off-site recovery rehearsal

**State: prepared, not yet run against current staging providers.** The saved Supabase staging hostname in `.env.auth-feasibility.local` failed DNS resolution on 2026-09-28. Provider-backed recovery evidence must not be inferred from a passing syntax or lint check.

The narrowly scoped script `scripts/pilot-evidence-offsite-rehearsal.mjs` creates one synthetic PDF under a new `ticket07-synthetic/` key in the private staging `pilot-student-evidence` bucket. It reads the bytes from Supabase, encrypts them with AES-256-GCM, writes a versioned B2 object under a `ticket07synthetic/` prefix, reads that exact version back, verifies its checksum and authentication tag, deletes only its source synthetic object, restores the bytes to a second new synthetic key, checks the restored bytes and anonymous public access, then deletes the restored object. The encrypted B2 object remains for an independent readback. The output includes its exact key, version ID, checksums, timestamps, and access status, but no credentials or evidence content.

Use a separate staging Supabase project and a B2 application key restricted to a synthetic-only bucket or prefix. Put credentials in ignored local environment files; do not paste them into an issue or commit. Required variables are `PILOT_EVIDENCE_SUPABASE_URL`, `PILOT_EVIDENCE_SUPABASE_SERVICE_KEY`, `PILOT_BACKUP_B2_ENDPOINT`, `PILOT_BACKUP_B2_BUCKET`, `PILOT_BACKUP_B2_KEY_ID`, `PILOT_BACKUP_B2_KEY`, `PILOT_BACKUP_B2_PREFIX` (starting with `ticket07synthetic/`), `PILOT_BACKUP_ENCRYPTION_KEY` (base64-encoded 32 bytes), and `PILOT_EVIDENCE_SYNTHETIC_APPROVED=true`. Run `node --env-file=<ignored-local-file> scripts/pilot-evidence-offsite-rehearsal.mjs` only after checking the target project and bucket in the dashboard. Save the JSON output and actual provider operation usage in the ignored `.scratch/pilot-readiness/` directory before adding a redacted result here.
