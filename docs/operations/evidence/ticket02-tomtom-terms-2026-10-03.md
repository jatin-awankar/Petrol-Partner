# Ticket 02 — TomTom routing terms and mode evidence (2026-10-03)

**Finding: TomTom is not approved for the current immutable-route design.** This is a first-party source review, not a legal opinion or a live API rehearsal. The [TomTom Portal Terms & Conditions](https://docs.tomtom.com/legal/terms-and-conditions) define **Results** in clause 1 to include route information returned by Maps APIs. Clause 11.4 prohibits caching or storing Results except for client caching when response control headers are present, only for the maximum age they indicate, with invalidation on content updates where supported. It expressly excludes caching to serve multiple clients. The [v1 Calculate Route response](https://docs.tomtom.com/routing-api/documentation/tomtom-maps/v1/calculate-route) lists `Cache-Control: no-cache, no-transform`; it supplies no positive `max-age` for a durable client cache. There is **no published permission or retention period in that clause for a server-side immutable copy** of route geometry, distance progression, or duration. Clause 16.1's duty to retain commercial usage records for audit does not override clause 11.4's restriction on API Results. The 90-day limit in clause 11.6.12 applies to downloaded Map Data and Traffic Analytics Products, not Routing API Results; TomTom's own request-metadata retention statement is also not a customer storage licence.

The current schema stores `posted_route_offers.geometry`, `cumulative_meters`, `distance_meters`, and `duration_seconds` in PostgreSQL ([migration 0037](../../../apps/api/src/db/migrations/0037_posted_route_offers.sql)); the route and quote services read these fields as the durable route version ([repository](../../../apps/api/src/modules/posted-routes/posted-routes.repo.ts), [service](../../../apps/api/src/modules/posted-routes/posted-routes.service.ts)). If populated from TomTom's response, geometry, distance, and duration are Results covered by clause 11.4. Computing a cumulative-distance array from TomTom's path does not establish a separate retention right; clause 11.6.1 also restricts derivative databases. Driver-entered origin/destination or a driver-drawn input path are not *merely by being sent to TomTom* TomTom Results, but that distinction does not authorize storing TomTom's returned or corrected path/progression. An input-only design would need a separate engineering and terms review before replacing the approved server-verified immutable route policy.

Other first-party evidence:

- **Modes:** [Routing v1 `travelMode`](https://docs.tomtom.com/routing-api/documentation/tomtom-maps/v1/calculate-route) lists `car` and `motorcycle`; `motorcycle` is beta, restriction data is incomplete in some areas, and a route section can report `other` when the requested mode is unavailable. It has no `scooter` mode or API statement that `motorcycle` accurately covers scooters. TomTom's consumer scooter navigation products do not establish Routing API mode semantics. The [Orbis v3 migration guide](https://docs.tomtom.com/routing-api/documentation/tomtom-orbis-maps/v3/product-information/migration-guide) supports `car` and `taxi`, not `motorcycle`.
- **Map display and attribution:** The [v1 introduction](https://docs.tomtom.com/routing-api/documentation/tomtom-maps/v1/product-information/introduction) explicitly describes plotting route geometry on another map supplier's tiles, which supports Mapbox display as a documented use case. The [Portal Terms, clause 17.3](https://docs.tomtom.com/legal/terms-and-conditions), still requires preserving generated copyright marks or implementing the TomTom Copyright API for other Maps API services. Display permission does not grant server retention permission.
- **Commercial use and quota:** The [platform FAQ](https://docs.tomtom.com/platform/documentation/status-and-support/faqs) says commercial applications may be built during free evaluation. The [pricing page](https://docs.tomtom.com/pricing) lists 20,000 free Routing API requests per month without a credit card, including TomTom Maps and Orbis Maps; the FAQ says requests return HTTP 429 when free limits or prepaid balance are exhausted. [Default Routing QPS is five](https://docs.tomtom.com/platform/documentation/api-best-practices/qps-limits). The Portal Terms distinguish an accepted Subscription Plan/Permitted Solution licence (clause 2.1) from internal Evaluation Use (clause 2.2). The account's actual plan and any separate written agreement were not inspected. Thus the FAQ is evidence for commercial *building*, but does not itself settle this account's production licence or the retention conflict. Clause 14.2 permits suspension for quota breaches and specifically for creating extra accounts to obtain more free requests.
- **Version support:** The [pricing page](https://docs.tomtom.com/pricing) says previous-generation TomTom Maps APIs continue to be supported while some are being deprecated and recommends Orbis for new integrations. The [v1 Calculate Route documentation](https://docs.tomtom.com/routing-api/documentation/tomtom-maps/v1/calculate-route) is still published. No source reviewed here guarantees a production lifetime for v1 motorcycle routing or an equivalent replacement in Orbis v3.

**Decision for this ticket:** Do not resolve the provider gate or enable TomTom-backed real bookings under the present route-storage design. A synthetic adapter/rehearsal may proceed within the account's evaluation allowance; it must not persist real TomTom Results in the production schema. To reconsider TomTom, obtain a written amendment/permission that explicitly covers retained geometry, cumulative distances and duration for the required audit period (including backup copies), or approve and implement a substantially different route-authority and audit design after separate review. Also verify the actual account plan, attribution implementation, local v1 motorcycle sections and restrictions, quota failure behaviour, and v1 availability before production use.
