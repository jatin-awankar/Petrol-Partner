**Decision: NO-GO for a real-trip zero-cost arrangement.** This run proves a narrow synthetic database export and restore with one versioned B2 object. ## Provider and execution boundary

The dated [provider refresh](ticket07-provider-refresh-2026-09-28.md) records published free allowances: B2's first 10 GB, Resend's 3,000 messages/month and 100/day, Cloudflare Workers Free's 10 ms CPU/invocation and five Cron Triggers, Vercel Hobby's daily cron, and Supabase Free's pausing and lack of managed database backups. **This run measured none of those account quotas, scheduled invocation timing, email delivery, or commercial eligibility.** It incurred no known charge; the actual B2 operation/bandwidth bill and future overage exposure were not read from the account. No recurring zero-cost scheduler or independent monitor account was configured. No provider deployment was made.

The backup command requires `pg_dump`, `pg_dumpall`, and `tar`. The restored object test did not include a source private storage service. Until a complete off-site export of database **and** private evidence objects can be scheduled and restored with retained keys, a serverless sweep would increase operational complexity without proving the recovery prerequisite. The existing worker remains unchanged. The next gate is a synthetic Supabase Storage-to-B2 export/restore plus an hourly scheduler and independent alert receipt measured on an accessible permitted free account. Real bookings remain disabled.
