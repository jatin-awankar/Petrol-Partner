# Ticket 11 synthetic backup and restore evidence — 2026-09-25

## Source and scope

The source was a newly created disposable PostgreSQL 17.6 database, `ticket11_source2_test`, inside the repository's tmpfs-backed Docker Compose service. Migration `0001` through `0011` was applied. Before backup it contained one synthetic allowlisted operator, zero pause operations, and zero verification rows. No raw verification object store was used. The empty restore target was `ticket11_restore2_test`. Both databases were inventoried before use. No deployed or real-user database was modified.

The independent storage destination was the private Backblaze B2 bucket `synthetic-recovery-receipts`, under a fresh `ticket11synthetic/` namespace. The scoped writer key uploaded an AES-256-GCM-encrypted custom-format PostgreSQL dump, global role export, and restoration metadata. A separate B2 reader key retrieved the metadata. The encryption key for this synthetic exercise is in an ignored mode-0600 local recovery file outside either database; this is not evidence of second-operator custody or a production key-recovery arrangement.
