# Independent notification watch and urgent outreach

Run `npm run monitor:notifications` every minute from a scheduler outside the API and worker deployment. It uses a read-only `MONITOR_DATABASE_URL`, `PILOT_OUTAGE_ALERT_ENDPOINT` (HTTPS), and `PILOT_OUTAGE_ALERT_TOKEN`. The endpoint must lead to an operator paging channel independent of the pilot email gateway and worker. The monitor posts only signal codes, count, and observation time. It exits nonzero if the alert gateway fails. The scheduler must page on repeated nonzero exits. Configure approved `PILOT_SUPPORT_WINDOW_START` and `PILOT_SUPPORT_WINDOW_END` as ISO timestamps for the active operating window; update them for each window. Test an actual worker stop and alert receipt at the chosen provider before real trips. The command has no worker dependency. Database failure also alerts through this separate endpoint.

The online outreach action uses the protected mutation receipt store and is acknowledged only after independent signed evidence is durable. Committed but unevidenced records enter restricted mode; recovery reconciliation restores signed records and audit history.

The protected console reports worker heartbeat, the oldest ready queued event, queue size, late first attempts, failures, last successful delivery, and exhausted jobs. A healthy worker polls each ten seconds and initial jobs are due immediately; the one-minute target requires worker and provider health. The monitor alerts when worker heartbeat or oldest important ready event exceeds five minutes and when the queue reaches 20. The monitor does not mark email failure as a recovery-evidence failure. Operator retry resets only the exhausted email job; it never invokes the originating business action. The five-attempt budget remains in PostgreSQL.

For urgent participant support, a current MFA operator records participant ID, method, time, coded reason, and coded outcome in the console. Do not enter phone numbers or message content. During primary outage, each pre-authorized operator uses an individually provisioned private credential file on a separate host. The credential is a 0600 regular JSON file containing `operatorId`, a random `signingSecret` of at least 32 characters, and a private hex `totpSecret` of at least 20 bytes. Provision and revoke these credentials during the operator access review; keep them outside the database backup. The CLI verifies a six-digit one-time code and reads participant details from standard input, keeping them out of process arguments and shell history:

`PILOT_OUTAGE_OUTREACH_PATH=/private/path/outreach.jsonl PILOT_OUTAGE_OPERATOR_CREDENTIAL_PATH=/private/path/operator.json npm run outreach:fallback -- record`

Pass one JSON object on stdin with `participantId`, `method`, `reason`, `outcome`, and `otp`. Use a private terminal input method that does not echo or save the JSON. Use a separate signed file for each operator, paired with that operator’s credential. The command fsyncs each signed entry and the directory. Store the signed file and signing credentials in separately recoverable private storage. The UUID, method and coded values are the only recorded participant details. Offline revocation cannot be checked until reconciliation, which requires current operator status; lost or stale offline credentials require incident review.

After restoration, inspect the file and run `npm run outreach:fallback -- reconcile` with `DATABASE_URL` and the same path and individual credential. Reconciliation checks signatures, participant and current operator status, then inserts records and audit rows transactionally and idempotently. An unrecognized operator, missing participant, or bad signature requires manual review before reopening writes. Keep the signed fallback file until the recovery review is complete and the database and backup contain the reconciled records. The operator's manual recovery decision must explicitly account for this file; the current automated recovery gate does not inspect it.

This implementation leaves real trips disabled. Deployment and live provider receipt have not been demonstrated by local tests.
