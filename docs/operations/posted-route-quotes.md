# Passenger posted-route previews

Ticket 11 extends the existing route preparation, matcher, pricing, audit and receipt implementation. It does not enable production discovery, publication, quotes, requests or bookings. Passenger exposure has a hard non-test gate; driver-private preparation remains available under ticket 10's controls. No migration or live-data change is needed: publication and stop declarations are optional immutable members of the existing `route_verification` snapshot. Historical snapshots remain unchanged.

## Confirmation and publication

1. An eligible driver calls `POST /v1/posted-routes/preview` with the existing preparation fields and optionally `stop_points` (2–20 longitude/latitude pairs). The server returns the saved-route preview digest plus each requested point, actual matched point and position along the route. It checks the approved Amravati artifact, precision, unique route position and pinned Valhalla road correspondence. Matching alone never certifies stopping safety.
2. The driver calls the existing protected `POST /v1/posted-routes` with the fresh endpoint confirmation and optional `passenger_publication.stops`. Each stop includes a stable local `id`, public meeting-place `name`, requested `point`, exact confirmed `matched_point`, and explicit `safe_stopping_place`, `legal_stopping`, `correct_side` and `correct_direction` declarations. Bikes and scooters also require `helmet_space`. All declarations must be true. The driver confirms actual map positions; the server never silently moves them.
3. Without `passenger_publication`, the offer stays driver-private. With it, successful acknowledged preparation has `visibility: published` for the gated passenger preview. The route's database lifecycle status remains `prepared`; publication visibility is independent. Stops, route version and area evidence are captured together by the existing transaction, audit-linked operation, notification and signed recovery receipt. A different payload cannot reuse the idempotency key. This is a self-declaration, not a platform certification of legality or safety.
4. Published stops are immutable. A different meeting place requires a new verified offer; after any request, use the existing audited cancellation/replacement rule. This ticket does not add a passenger-authored stopping-place request or a driver messaging channel. Passengers select from explicitly confirmed places; an arbitrary point without prior driver confirmation cannot get a quote.

## Passenger reads and quote

`GET /v1/posted-routes` discovers up to 100 candidate future publications, filtering current driver/vehicle eligibility, route and operating policy, support coverage, acknowledged saved evidence and current area approval. A current adult declaration and unrestricted account are required. `GET /v1/posted-routes/published/:id` is the separate passenger detail seam. The existing `/:id` and `/mine` remain owner reads. Passenger responses contain geometry, confirmed stops, schedule, version, category, rate and service-area limitations, but exclude driver IDs, vehicle declaration IDs, registration, contacts and private provider/recovery evidence. All responses are private/no-store.

`POST /v1/posted-routes/:id/quote` accepts only `route_version`, `pickup` and `dropoff`. It rejects self-quotes, stale versions or evidence, unavailable approval, expired/held/cancelled offers, restrictions, absent declarations, unavailable support, pause or restricted recovery, off-route/ambiguous/reversed points and unconfirmed or unsafe stops. Requested and matched points must both satisfy the pinned Amravati coordinate envelope. The matcher allows one continuous pass through dense geometry while rejecting distinct passes or crossings.

Quote verification checks the independently acknowledged route evidence and uses the pinned graph's `locate` response to validate road correspondence. It uses the same two-job bound and 10-second timeout as route verification. Graph mismatch, overload, malformed/unavailable responses or ambiguous roads fail closed. It never calls point-to-point routing to determine the price. Safe reads and quote reads serialize with route state changes; a quote remains a preview and cannot reserve capacity.

Distance is the ordered difference along saved cumulative metres, rounded to integer metres with a 500 m minimum before rounding. Rates are 500 paise/km for bike/scooter and 700 for car. Integer arithmetic rounds once to nearest paise, exact halves upward. Quotes include route/version, policy, requested/matched points, stop IDs, measured distance, source, category, rate, rounding, INR, total paise, zero additional charges, expiry at request cutoff and invalidation on route change. `preview_only: true` and `real_bookings_enabled: false` are explicit. No request, allocation, charge, notification or durable quote state is created by quoting.

Ticket 12 owns protected request/acceptance revalidation and freezing; ticket 15 owns integrated browser flow. Neither a quote nor a publication authorizes real trips. External/rate review, hosting/gateway and licence compliance, representative migration, configured staging/recovery and ticket 18's explicit activation decision remain downstream launch requirements.
