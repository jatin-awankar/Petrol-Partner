Submitting fabricated, invalid credentials on the PR #78 Vercel preview returned `500 INTERNAL_SERVER_ERROR` with the visible message “Internal server error.” The same request sent directly to the existing Render API returned 500, so the Vercel rewrite alone does not explain it. A read-only inventory of the pooler previously documented as the Render target found only migrations `0001`–`0003`, zero users, and no `auth_cutover_state` table. The live Render `DATABASE_URL` was not independently inspected, so the missing table is a strong explanation rather than a verified runtime configuration fact. No migration was applied to that existing database.

The maintainer selected an **isolated synthetic preview backend**. In the Petrol Partner Render workspace, a new Free PostgreSQL 17 database named `petrol-partner-pr78-synthetic-db` was created in Singapore. Its creation form showed a $0 monthly total; the dashboard says it expires on **2026-11-01**. Before migration, it contained zero public tables. A separate runtime role was created without schema creation rights. The repository's 42 forward migrations were applied with the migration role; `db-migrate --check` verified all 42 checksums. A runtime-role check found zero users, no schema creation permission, and legacy login authorized in the new database. The local API, built from this branch and connected only to that synthetic database, returned 200 from `/v1/health` and `401 INVALID_CREDENTIALS` for the same fabricated invalid sign-in. This closes the database-path reproduction locally, but **the remote preview is not fixed yet**: the Free API service has not been deployed, no synthetic account has been registered, and the Vercel preview still targets the existing API.
